# 活世界自主推进（开发预览）

本功能位于 `feat/autonomous-world-mvp`，独立于人物卡的普通 Guide。默认关闭，用户需在当前游戏右侧 **酒馆状态 → 活世界 · NPC 自主生活** 手动启用。

## 当前已经实现

- 即使玩家停止输入，只要 DSH Tavern 服务端仍在运行，就按设置的真实时间间隔（1 / 5 / 15 / 30 / 60 分钟）推进虚构世界时间。
- 每轮只让少量 NPC 推进当前个人目标、轮换待办、保存最近行动摘要，避免为所有人物同时调用大模型。
- 优先读取本局人物台账、人物设计档案；同时支持从本局世界书「固定人物档案」中识别群像（例如「崇祯朝·群像人生穿越」中约 150 位人物）。不把关键词/地点误当作人物。
- 在独立收件箱中呈现传闻、日常活动、可供后续剧情采用的来信和朝政消息；下一轮生成正文时作为**尚待核实的信息**注入前台。
- 自动推进设置及NPC活动存在独立的本地 JSON；服务端重启时扫描已启用的游戏并恢复定时器，落后太久只补算最多 12 步（避免沉睡设备恢复后雪崩）。
- 处理重复定时器、游戏正在生成时避让、暂停、已读、有限事件队列。没有额外模型调用，因而没有自动生成 token 费用。

## 明确边界

**这不是完整的多智能体世界。** 本阶段后台 NPC 活动由可复现的规则驱动，并非数百个人物各自独立连接 LLM；不会自行发布真实官职任免、结算战役、改变领土、扣除国库金银或代替玩家接受求婚/赐婚。相关内容只作为传闻与提案，直到权威游戏剧情确认。不会在聊天记录中伪造「玩家」输入。

**游戏服务不运行时不会实时模拟**。下次启动会补算最多 12 步；这是一次恢复计算，而不是离线期间持续执行。游戏时间和外界现实时间也不等同。

**独立侧载状态还没有并入游戏 ZIP 存档的导入/导出与任意剧情分支回退。** 本次增量不修改 DSH 的权威 Story Timeline，因此侧载报告只被视为非权威观察信息，不能取代主故事事实。若要做战争/财政真结算，必须先设计事务和回退机制。

NPC 姓名来源以导入角色卡的现有世界书和人物档案为准。不会随意把一位陌生宫女、后妃直接当作平民玩家已知的密友；远方军事活动通常只是尚待确认的消息。

## 开发测试

```bash
node --test tests/autonomous-world.test.mjs
node --check tavern-plugin/lib/domain/autonomous-world.js
node --check tavern-plugin/lib/index.js
node bin/build-tavern-client.mjs --check
```

更完整的实机验收建议：

1. 导入崇祯群像卡，启用活世界，设置真实时间 1 分钟、世界步长 1 小时。
2. 点击一次「现在推进一步」，应读取世界书名册，出现 NPC 行动/来信；不应出现模型请求。
3. 不发送玩家消息，等待 2–3 次间隔，NPC 的 `progress`、`memory`、收件箱继续增长。
4. 正在生成正文或后台结算时，应暂缓世界步进，不抢占当前回合。
5. 退出网页但**保持 DSH 服务端运行**，稍后重新打开同局，应看到累计步数已变化。
6. 重启服务器，不打开任何页面也应恢复已启用的会话（以日志和步数核验）。
7. 关闭开关：步数停止，但既有收件箱与记忆不被删除。
8. 回退或重写正文后检查报告仍保持「待核实」性质，而非被错误写入已发生的正式剧情。

## 后续演进

下一阶段应从当前独立且低成本的活动规则升级为受权限约束的任务系统：给角色明确地点、关系、消息来源、行动成本与长期计划，由合并的世界事务结算统一校验。不应为 150 位 NPC 各创建一个永久 LLM Session；推荐只针对高影响力事件按需委派后台模型，其他 NPC 用确定性状态机推进。
